Save every article of a blog or news section in one file.

A blog or a news section is a long list of articles with a “Next” link at the bottom. Grab All Files finds the articles, lets you drop the ones you do not want, and saves them as one HTML with contents and search, one long printable HTML, or Markdown. On the Free plan you save one article per run; Pro saves the whole selection at once.

Three ways to find the articles

The candidate list is built from what you point it at. You can also pick “This page’s links” or paste a list of URLs.

Sitemap

If the site publishes a sitemap, every listed URL becomes a candidate. Looking at the candidate count is a quick way to see how many articles the site lists.

Same path

Start from the blog’s list page and collect the pages under the same path, such as everything below the blog folder. It leaves out the rest of the site.

“Next” links on the list pages

Links marked next, “Next”, “Older” and similar are recognised. The list is followed page by page to find the candidates. Up to 100,000 candidates are found.

The candidate list

Candidates appear with their title and address, and two boxes narrow them down.

Choosing the form of the saved file

FormWhat you getGood for
HTML with contents and searchAll articles in one HTML file, with a table of contents and a search boxReading on screen and finding a phrase across hundreds of articles. The smallest of the forms.
Vertically joined HTML (for printing)Articles joined top to bottom, with a page break between them when printedPrinting, or a PDF: use the browser’s print dialog and save as PDF. Grab All Files does not create the PDF itself.
MarkdownOne Markdown file, or one per article, with source_url and captured_at on each pageNotes, a personal archive, or giving the text to an AI service you choose. See the Markdown guide below.

For articles, “Easy to read” is usually the right look: it is faster and the file is lighter. “Keep the original look” keeps each article’s layout, fonts and images, at the price of a longer run and a bigger file.

Steps for a whole blog

  1. 1Open the blog’s list page, the one that shows the newest articles, not an individual article. Sign in first if the site needs it.
  2. 2Open Grab All Files and switch to “Combine pages into HTML”. Under where to collect from, choose the sitemap, “Same path” or the page’s links.
  3. 3Wait for the candidate list. Use the filter and exclude boxes to drop pages that are not articles: tag pages, category pages, author pages, the about page.
  4. 4With Pro, select the articles and put them in the order you want. Newest first is not guaranteed, so check the order.
  5. 5Choose the look and the form, then save. Open the saved file and check the first and last articles, the count, and a search for a phrase you know is in the middle.

When this is the wrong tool

Grab All Files opens articles through the browser, so a run over several thousand articles takes a long time and produces a very large file. For a news archive of that size, a desktop website copier that requests pages directly from the server is the better choice, though it cannot see pages that need your sign-in.

A list that loads more items as you scroll, instead of using “Next” links, is a different case. Read the guide on infinite scroll before you start.

자주 묻는 질문

How do I save every post of a blog at once?

Open the blog’s list page, choose the sitemap, “Same path” or the page’s links, drop the non-article pages from the candidate list, and save with Pro in one run. On the Free plan you save one article per run and add the rest one at a time.

Does it follow “Next” and “Older posts” links?

Yes. Links such as next, “Next” and “Older” are recognised and followed to find candidates. With Pro it can also save all the continuing pages in one run.

Can I get a PDF of all the articles?

Save as “Vertically joined HTML (for printing)”, open it in the browser and use the print dialog to save as PDF. Each article starts on a new page when printed.

How can I search across all the saved articles?

Save as “HTML with contents and search”. The one HTML file has a table of contents and a search box that works offline in the browser.

Will it include comments?

Comment sections are a separate task. See the guide on saving and analysing comments; this page covers the articles themselves.
